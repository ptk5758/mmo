## 2. 서비스 개요

### 2.1 서비스 목적

사용자가 지도에서 원하는 위치를 마커로 등록하고, 해당 위치에 설정된 반경 안으로 진입하면 앱이 이를 감지하여 사용자에게 로컬 알림을 제공한다.

마커 데이터의 등록과 관리는 앱이 포그라운드인 상태에서 수행한다. 활성화된 마커의 반경 진입 감지는 앱이 백그라운드인 상태에서도 동작하도록 구성한다.

### 2.2 주요 사용자

특정 장소에 가까워졌을 때 해야 할 일이나 방문 목적을 알림으로 확인하려는 개인 사용자를 대상으로 한다.

### 2.3 핵심 사용자 가치

- 사용자가 원하는 장소를 지도에서 직접 지정할 수 있다.
- 장소마다 서로 다른 알림 반경과 알림 내용을 설정할 수 있다.
- 앱을 계속 열어 두지 않아도 장소 접근 알림을 받을 수 있다.
- 특정 장소의 최초 방문 여부를 자동으로 기록할 수 있다.
- 위치 권한을 허용하지 않아도 마커 자체는 관리할 수 있다.

### 2.4 주요 용어

| 용어 | 정의 |
|---|---|
| 마커 | 사용자가 지도에 등록한 위치 기반 알림 지점 |
| 알림 반경 | 마커를 중심으로 진입 여부를 판단하는 거리 |
| 지오펜스 | 특정 위치와 반경으로 구성된 가상의 영역으로, 운영체제가 사용자의 진입 또는 이탈을 감지 |
| 진입 이벤트 | 사용자가 마커 반경 밖에서 안으로 이동했을 때 발생하는 이벤트 |
| 최초 진입 | 특정 마커의 진입 이벤트가 처음으로 확인된 상태 |
| 방문 완료 | 사용자가 해당 마커를 방문한 것으로 표시된 상태 |
| 활성화 | 사용자가 해당 마커를 위치 추적 대상으로 지정한 상태 |
| 추적 상태 | 해당 마커가 운영체제 위치 감지 기능에 실제로 등록되었는지를 나타내는 상태 |
| 로컬 알림 | 외부 서버 없이 기기에서 직접 생성하여 표시하는 알림 |
| 알림 제한 시간 | 동일 마커의 반복 알림을 방지하기 위해 알림을 생략하는 시간 |

## 3. 적용 범위

### 3.1 포함 범위

- 지도에서 위치를 선택하여 마커 등록
- 마커별 이름, 설명, 알림 반경 및 알림 문구 설정
- 마커 목록 및 상세 정보 조회
- 마커 정보 수정
- 마커 삭제
- 마커별 위치 추적 활성화 및 비활성화
- 활성화된 마커의 백그라운드 진입 감지
- 진입 시 로컬 알림 표시
- 동일 마커의 중복 알림 제한
- 알림 선택 시 마커 상세 화면 이동
- 최초 진입 기록
- 최초 진입 시 선택적인 방문 완료 자동 처리
- 위치 권한 상태에 따른 기능 제어
- 마커 및 처리 상태의 기기 내부 저장
- 앱 재실행 시 데이터 및 추적 상태 복구

### 3.2 제외 범위

- 회원가입 및 로그인
- 서버 및 외부 데이터베이스
- 여러 기기 간 데이터 동기화
- 서버에서 전송하는 원격 푸시 알림
- 마커 공유 및 협업
- 초기 버전의 Android 지원
- 초기 버전의 클라우드 백업 및 복원
- 웹 애플리케이션 제공

### 3.3 전제 조건

- 사용자는 지도와 위치 기능을 이용할 수 있는 iOS 기기를 사용한다.
- 기기 자체의 위치 서비스가 켜져 있어야 백그라운드 진입 감지가 가능하다.
- 백그라운드 위치 감지를 위해 필요한 수준의 위치 권한을 사용자가 허용해야 한다.
- 로컬 알림 표시를 위해 알림 권한이 필요할 수 있다.
- 위치 감지 시점과 정확도는 기기 상태 및 운영체제 정책의 영향을 받을 수 있다.

## 6. 상세 기능 요구사항

### 6.1 지도

#### FR-MAP-001 지도 표시

| 항목 | 내용 |
|---|---|
| 설명 | 앱은 사용자가 위치를 확인하고 마커를 선택할 수 있는 지도를 표시해야 한다. |
| 사전 조건 | 지도 화면에 진입한 상태 |
| 입력 | 지도 이동, 확대 및 축소 조작 |
| 처리 | 지도와 등록된 마커를 표시 |
| 결과 | 사용자가 지도 위치와 등록 마커를 확인 |
| 예외 | 현재 위치 권한이 없더라도 지도 탐색과 저장된 마커 표시는 가능해야 함 |
| 관련 항목 | FR-MAP-002, FR-MRK-002 |

**수용 기준**

1. 지도 화면에 진입하면 지도가 표시되어야 한다.
2. 저장된 마커가 존재하면 해당 좌표에 마커가 표시되어야 한다.
3. 위치 권한이 없어도 지도 탐색이 차단되지 않아야 한다.

#### FR-MAP-002 지도에서 위치 선택

| 항목 | 내용 |
|---|---|
| 설명 | 사용자는 지도에서 원하는 위치를 직접 선택할 수 있어야 한다. |
| 사전 조건 | 지도 화면에 진입한 상태 |
| 입력 | 지도상의 위치 선택 |
| 처리 | 선택한 위치의 위도와 경도를 임시 선택 상태로 저장 |
| 결과 | 선택 위치를 화면에 표시하고 마커 등록을 시작할 수 있음 |
| 예외 | 유효한 좌표를 얻지 못하면 등록 화면으로 이동하지 않음 |
| 관련 항목 | FR-MRK-001 |

**수용 기준**

1. 사용자가 지도에서 위치를 선택하면 선택 위치가 시각적으로 표시되어야 한다.
2. 선택한 위치의 위도와 경도가 마커 등록 화면에 전달되어야 한다.
3. 사용자는 현재 위치가 아닌 다른 위치도 선택할 수 있어야 한다.

### 6.2 마커 관리

#### FR-MRK-001 마커 등록

| 항목 | 내용 |
|---|---|
| 설명 | 사용자는 지도에서 선택한 위치에 새 마커를 등록할 수 있어야 한다. |
| 사전 조건 | 지도에서 유효한 위치를 선택 |
| 필수 입력 | 위치, 이름, 알림 반경, 알림 제목, 알림 내용 |
| 선택 입력 | 설명 |
| 옵션 | 추적 활성화 여부, 최초 진입 시 방문 완료 자동 처리 여부 |
| 처리 | 입력 검증 후 고유 ID와 생성 시각을 부여하여 로컬 저장소에 저장 |
| 결과 | 마커가 저장되고 지도, 목록 및 상세 화면에서 조회 가능 |
| 예외 | 위치 권한이 없으면 마커만 저장하고 위치 추적은 시작하지 않음 |
| 관련 항목 | FR-MAP-002, FR-LOC-001, FR-DAT-001 |

**수용 기준**

1. 필수 항목이 유효하면 마커가 로컬 저장소에 저장되어야 한다.
2. 저장된 마커는 앱을 종료한 뒤 다시 실행해도 조회되어야 한다.
3. 마커별로 서로 다른 알림 반경을 저장할 수 있어야 한다.
4. 위치 권한이 거부된 상태에서도 마커 등록에 성공해야 한다.
5. 위치 권한 없이 활성화된 마커는 추적 불가 상태로 구분되어야 한다.
6. 필수 항목이 누락되거나 유효하지 않으면 저장하지 않고 오류를 안내해야 한다.

#### FR-MRK-002 마커 목록 조회

| 항목 | 내용 |
|---|---|
| 설명 | 사용자는 저장된 전체 마커를 목록으로 조회할 수 있어야 한다. |
| 표시 정보 | 이름, 활성화 여부, 추적 상태, 알림 반경, 방문 완료 여부 |
| 결과 | 사용자가 선택한 마커의 상세 화면으로 이동 가능 |
| 관련 항목 | FR-MRK-003 |

**수용 기준**

1. 저장된 마커가 목록에 표시되어야 한다.
2. 마커가 없으면 데이터가 없음을 알리는 빈 상태 화면이 표시되어야 한다.
3. 활성화 상태와 실제 추적 상태를 구분하여 확인할 수 있어야 한다.

#### FR-MRK-003 마커 상세 조회

| 항목 | 내용 |
|---|---|
| 설명 | 사용자는 선택한 마커의 전체 정보와 상태를 조회할 수 있어야 한다. |
| 표시 정보 | 위치, 이름, 설명, 반경, 알림 문구, 활성화 상태, 추적 상태, 최초 진입 및 방문 완료 정보, 마지막 알림 시각 |
| 진입 경로 | 지도, 마커 목록, 로컬 알림 |
| 관련 항목 | FR-MRK-004, FR-MRK-005, FR-NOT-003 |

**수용 기준**

1. 선택한 마커와 일치하는 정보가 표시되어야 한다.
2. 상세 화면에서 수정, 활성화·비활성화 및 삭제 기능에 접근할 수 있어야 한다.
3. 알림을 통해 진입한 경우 알림에 포함된 마커가 표시되어야 한다.

#### FR-MRK-004 마커 수정

| 항목 | 내용 |
|---|---|
| 설명 | 사용자는 등록된 마커의 위치와 설정을 수정할 수 있어야 한다. |
| 수정 가능 항목 | 위치, 이름, 설명, 반경, 알림 제목·내용, 활성화 여부, 방문 완료 자동 처리 옵션 |
| 처리 | 입력 검증 후 데이터 저장, 위치 감지 조건 변경 시 지오펜스 재등록 |
| 결과 | 수정 내용이 지도, 목록, 상세 및 백그라운드 감지에 반영 |
| 예외 | 지오펜스 재등록이 실패해도 수정된 마커 데이터는 유지하고 추적 실패 상태를 표시 |
| 관련 항목 | FR-LOC-001, FR-LOC-002, FR-DAT-001 |

**수용 기준**

1. 유효한 수정 내용은 로컬 저장소에 반영되어야 한다.
2. 위치 또는 반경이 변경된 활성 마커는 변경된 조건으로 지오펜스가 갱신되어야 한다.
3. 위치 권한이 없으면 수정 내용만 저장되고 지오펜스는 등록되지 않아야 한다.

#### FR-MRK-005 마커 삭제

| 항목 | 내용 |
|---|---|
| 설명 | 사용자는 마커를 영구적으로 삭제할 수 있어야 한다. |
| 사전 조건 | 삭제할 마커가 존재 |
| 처리 | 삭제 확인 후 지오펜스 해제 및 로컬 데이터 제거 |
| 결과 | 지도, 목록 및 상세 화면에서 마커가 제거 |
| 예외 | 지오펜스 해제가 실패하면 로컬 마커 삭제 후 정리 대상 상태를 남기는 방안을 기술 설계에서 정의 |
| 관련 항목 | FR-LOC-002, FR-DAT-001 |

**수용 기준**

1. 삭제 전에 사용자 확인 절차가 제공되어야 한다.
2. 삭제가 확정되면 마커 데이터가 로컬 저장소에서 제거되어야 한다.
3. 삭제된 마커의 지오펜스가 더 이상 유지되지 않아야 한다.
4. 삭제된 마커로 진입 알림이 발생하지 않아야 한다.

#### FR-MRK-006 마커 활성화·비활성화

| 항목 | 내용 |
|---|---|
| 설명 | 사용자는 마커별 위치 추적을 활성화하거나 비활성화할 수 있어야 한다. |
| 활성화 처리 | 사용자 설정을 활성화하고 조건 충족 시 지오펜스 등록 |
| 비활성화 처리 | 사용자 설정을 비활성화하고 지오펜스 해제 |
| 결과 | 비활성화해도 마커 데이터와 방문 기록은 유지 |
| 예외 | 권한이 없으면 활성화 설정은 유지하되 추적 불가 상태로 표시 |
| 관련 항목 | FR-LOC-001, FR-LOC-002, FR-PER-002 |

**수용 기준**

1. 비활성화한 마커는 데이터가 삭제되지 않아야 한다.
2. 비활성화한 마커에서는 진입 알림이 발생하지 않아야 한다.
3. 권한이 없는 상태에서 활성화를 선택해도 앱이 비정상 종료되지 않아야 한다.
4. 사용자 활성화 설정과 실제 추적 상태를 별도로 확인할 수 있어야 한다.

### 6.3 위치 감지

#### FR-LOC-001 지오펜스 등록

| 항목 | 내용 |
|---|---|
| 설명 | 앱은 활성화된 마커의 위치와 반경을 운영체제 위치 감지 기능에 등록해야 한다. |
| 사전 조건 | 마커 활성화, 필요한 위치 권한 허용, 유효한 좌표와 반경 |
| 입력 | 마커 ID, 위도, 경도, 반경 |
| 결과 | 실제 추적 상태를 등록 완료로 갱신 |
| 예외 | 권한 부족 또는 등록 실패 시 마커 데이터는 유지하고 실패 상태를 기록 |
| 관련 항목 | FR-MRK-001, FR-MRK-004, FR-MRK-006 |

**수용 기준**

1. 조건을 충족한 활성 마커는 운영체제 위치 감지 대상으로 등록되어야 한다.
2. 등록 성공과 실패 상태가 구분되어야 한다.
3. 등록 실패가 마커 데이터의 삭제로 이어지지 않아야 한다.

#### FR-LOC-002 지오펜스 해제

| 항목 | 내용 |
|---|---|
| 설명 | 앱은 비활성화, 삭제 또는 조건 변경 시 기존 지오펜스를 해제해야 한다. |
| 입력 | 마커 ID |
| 결과 | 해당 마커가 기존 조건으로 더 이상 감지되지 않음 |
| 관련 항목 | FR-MRK-004, FR-MRK-005, FR-MRK-006 |

**수용 기준**

1. 비활성화된 마커의 지오펜스가 해제되어야 한다.
2. 삭제된 마커의 지오펜스가 해제되어야 한다.
3. 위치나 반경 변경 시 기존 지오펜스를 해제한 뒤 새 조건을 등록해야 한다.

#### FR-LOC-003 백그라운드 진입 감지

| 항목 | 내용 |
|---|---|
| 설명 | 앱은 백그라운드 상태에서도 활성 마커의 반경 진입 이벤트를 처리해야 한다. |
| 사전 조건 | 필요한 위치 권한 허용, 마커 활성화, 지오펜스 등록 성공 |
| 입력 | 운영체제가 전달한 마커 식별자와 이벤트 시각 |
| 처리 | 마커 상태 확인 후 최초 진입, 방문 완료 및 알림 로직 실행 |
| 결과 | 관련 상태 저장 및 조건 충족 시 로컬 알림 표시 |
| 예외 | 삭제 또는 비활성화된 마커의 이벤트는 알림 없이 종료 |
| 관련 항목 | FR-ENT-001, FR-ENT-002, FR-NOT-001 |

**수용 기준**

1. 앱이 백그라운드인 상태에서 전달된 유효한 진입 이벤트를 처리해야 한다.
2. 비활성화되거나 존재하지 않는 마커에는 알림을 표시하지 않아야 한다.
3. 진입 이벤트 처리 결과가 로컬 저장소에 반영되어야 한다.

#### FR-LOC-004 추적 상태 복구

| 항목 | 내용 |
|---|---|
| 설명 | 앱은 저장된 활성화 설정과 운영체제의 실제 추적 상태가 다를 경우 이를 점검하고 복구해야 한다. |
| 실행 시점 | 앱 시작, 포그라운드 복귀, 권한 변경 확인 시 |
| 처리 | 활성 마커, 권한 및 실제 지오펜스 상태를 비교하여 등록 또는 해제 |
| 결과 | 가능한 범위에서 사용자 설정과 실제 추적 상태를 일치시킴 |
| 관련 항목 | FR-PER-003, FR-DAT-002 |

**수용 기준**

1. 앱 재실행 후 활성 마커의 추적 상태를 확인해야 한다.
2. 권한이 있고 등록이 누락된 활성 마커는 재등록을 시도해야 한다.
3. 비활성 또는 삭제된 마커의 불필요한 지오펜스는 해제해야 한다.

### 6.4 진입 및 방문

#### FR-ENT-001 최초 진입 기록

| 항목 | 내용 |
|---|---|
| 설명 | 앱은 특정 마커의 최초 진입 여부와 시각을 기록해야 한다. |
| 사전 조건 | 유효한 활성 마커의 진입 이벤트 수신 |
| 처리 | 진입 이력이 없으면 최초 진입 여부와 시각 저장 |
| 결과 | 이후 진입과 최초 진입을 구분 가능 |
| 관련 항목 | FR-ENT-002 |

**수용 기준**

1. 최초 진입 시 최초 진입 여부가 참으로 변경되어야 한다.
2. 최초 진입 시각이 저장되어야 한다.
3. 재진입 시 최초 진입 시각이 덮어써지지 않아야 한다.
4. 최초 진입 처리는 알림 표시 성공 여부와 관계없이 수행되어야 한다.

#### FR-ENT-002 방문 완료 자동 처리

| 항목 | 내용 |
|---|---|
| 설명 | 자동 완료 옵션이 활성화된 마커에 최초 진입하면 방문 완료 상태를 자동으로 활성화해야 한다. |
| 사전 조건 | 최초 진입이며 해당 마커의 자동 완료 옵션이 활성화 |
| 처리 | 방문 완료 여부와 완료 시각 저장 |
| 결과 | 상세 및 목록 화면에서 방문 완료 상태 확인 가능 |
| 예외 | 자동 완료 옵션이 비활성화되어 있으면 최초 진입만 기록하고 방문 완료 상태는 변경하지 않음 |
| 관련 항목 | FR-MRK-001, FR-ENT-001 |

**수용 기준**

1. 자동 완료 옵션이 켜진 마커의 최초 진입 시 방문 완료 상태가 참으로 변경되어야 한다.
2. 방문 완료 시각이 저장되어야 한다.
3. 자동 완료 옵션이 꺼진 마커는 최초 진입 후에도 방문 완료 상태가 자동 변경되지 않아야 한다.
4. 반복 진입이 기존 방문 완료 시각을 변경하지 않아야 한다.

### 6.5 알림

#### FR-NOT-001 진입 로컬 알림

| 항목 | 내용 |
|---|---|
| 설명 | 유효한 마커 진입 이벤트가 발생하면 해당 마커에 설정된 내용으로 로컬 알림을 표시해야 한다. |
| 사전 조건 | 마커 활성화, 진입 이벤트 유효, 중복 제한 조건 통과, 알림 표시 가능 |
| 입력 | 마커 ID, 알림 제목, 알림 내용 |
| 결과 | 사용자 기기에 로컬 알림 표시 및 마지막 알림 시각 저장 |
| 예외 | 알림 권한이 없으면 방문 관련 상태만 처리하고 알림은 표시하지 않음 |
| 관련 항목 | FR-LOC-003, FR-NOT-002 |

**수용 기준**

1. 조건을 충족하면 마커에 저장된 제목과 내용으로 알림이 표시되어야 한다.
2. 알림에는 해당 마커를 식별할 수 있는 정보가 포함되어야 한다.
3. 알림 표시가 완료된 경우 마지막 알림 시각이 저장되어야 한다.
4. 알림을 표시할 수 없어도 최초 진입과 방문 완료 처리는 수행되어야 한다.

#### FR-NOT-002 중복 알림 제한

| 항목 | 내용 |
|---|---|
| 설명 | 동일 마커에서 발생하는 반복 알림은 마지막 알림 후 1시간 동안 제한해야 한다. |
| 기준 단위 | 마커별 |
| 초기 제한 시간 | 1시간 |
| 관리 방식 | 코드의 공통 상수 |
| 결과 | 제한 시간 이내의 반복 알림 생략 |
| 관련 항목 | FR-NOT-001 |

**수용 기준**

1. 마지막 알림 후 1시간이 지나지 않은 동일 마커 이벤트에는 알림을 표시하지 않아야 한다.
2. 서로 다른 마커의 알림 제한 시간은 독립적으로 계산되어야 한다.
3. 마지막 알림 이력이 없거나 1시간 이상 경과하면 알림을 표시할 수 있어야 한다.
4. 중복 알림이 생략되어도 최초 진입과 방문 완료 처리는 정상 수행되어야 한다.
5. 제한 시간 값은 한 곳의 공통 상수 변경으로 조정할 수 있어야 한다.

#### FR-NOT-003 알림 선택 및 화면 이동

| 항목 | 내용 |
|---|---|
| 설명 | 사용자가 로컬 알림을 선택하면 해당 마커의 상세 화면으로 이동해야 한다. |
| 사전 조건 | 알림에 유효한 마커 ID가 포함됨 |
| 처리 | 앱 실행 또는 활성화 후 마커 ID로 상세 화면 이동 |
| 결과 | 해당 마커 상세 정보 표시 |
| 예외 | 마커가 이미 삭제된 경우 기본 화면으로 이동하고 필요 시 안내 표시 |
| 관련 항목 | FR-MRK-003 |

**수용 기준**

1. 앱이 종료, 백그라운드 또는 포그라운드인 상태에서 알림 선택을 처리할 수 있어야 한다.
2. 유효한 마커가 있으면 해당 마커 상세 화면을 표시해야 한다.
3. 해당 마커가 없으면 앱이 비정상 종료되지 않고 기본 화면으로 이동해야 한다.

### 6.6 권한

#### FR-PER-001 위치 권한 확인

| 항목 | 내용 |
|---|---|
| 설명 | 앱은 위치 추적을 시작하기 전에 현재 위치 권한 상태를 확인해야 한다. |
| 확인 상태 | 미결정, 필요한 수준으로 허용, 제한된 허용, 거부 |
| 결과 | 권한 상태에 맞는 추적 동작과 사용자 안내 수행 |
| 관련 항목 | FR-PER-002, FR-PER-003 |

**수용 기준**

1. 위치 추적 등록 전에 권한 상태를 확인해야 한다.
2. 권한 상태가 앱 화면의 추적 상태 안내에 반영되어야 한다.
3. 권한 요청을 거부해도 마커 관리 기능을 계속 사용할 수 있어야 한다.

#### FR-PER-002 위치 권한 거부 시 제한 처리

| 항목 | 내용 |
|---|---|
| 설명 | 위치 권한이 없으면 마커 데이터 관리는 허용하되 위치 추적 로직은 실행하지 않아야 한다. |
| 허용 기능 | 지도 탐색, 마커 등록·조회·수정·삭제 |
| 제한 기능 | 지오펜스 등록, 백그라운드 진입 감지 |
| 결과 | 마커는 저장하되 추적 불가 상태 표시 |
| 관련 항목 | FR-MRK-001, FR-MRK-006 |

**수용 기준**

1. 위치 권한을 거부해도 마커를 등록할 수 있어야 한다.
2. 위치 권한이 없으면 신규 지오펜스를 등록하지 않아야 한다.
3. 권한이 없는 상태를 사용자에게 확인 가능한 방식으로 표시해야 한다.
4. 권한 거부로 앱이 비정상 종료되지 않아야 한다.

#### FR-PER-003 권한 복구 후 추적 재등록

| 항목 | 내용 |
|---|---|
| 설명 | 위치 권한이 필요한 수준으로 허용되면 활성화 대상으로 저장된 마커의 추적을 등록하거나 복구해야 한다. |
| 사전 조건 | 위치 권한 복구, 활성화된 마커 존재 |
| 처리 | 활성 마커와 실제 추적 상태 비교 후 지오펜스 등록 |
| 결과 | 등록 성공 또는 실패 상태 표시 |
| 관련 항목 | FR-LOC-001, FR-LOC-004 |

**수용 기준**

1. 권한 복구 후 활성 마커의 지오펜스 등록을 시도해야 한다.
2. 비활성 마커는 자동으로 등록하지 않아야 한다.
3. 등록 결과가 실제 추적 상태에 반영되어야 한다.

### 6.7 데이터

#### FR-DAT-001 로컬 데이터 저장

| 항목 | 내용 |
|---|---|
| 설명 | 마커와 기능 수행에 필요한 상태를 기기 내부 로컬 저장소에 보관해야 한다. |
| 저장 대상 | 마커 정보, 활성화 상태, 최초 진입 상태, 방문 완료 상태, 마지막 알림 시각, 추적 상태 |
| 결과 | 서버나 외부 DB 없이 기능 수행 가능 |
| 관련 항목 | 전체 기능 요구사항 |

**수용 기준**

1. 마커 생성·수정·삭제 결과가 로컬 저장소에 반영되어야 한다.
2. 최초 진입, 방문 완료 및 마지막 알림 시각이 저장되어야 한다.
3. 저장 실패 시 성공으로 표시하지 않아야 하며 사용자 또는 로그에 실패 정보를 남겨야 한다.

#### FR-DAT-002 앱 재실행 시 데이터 복원

| 항목 | 내용 |
|---|---|
| 설명 | 앱을 종료한 뒤 다시 실행해도 저장된 마커와 설정을 복원해야 한다. |
| 처리 | 앱 초기화 시 로컬 데이터 로드 및 유효성 확인 |
| 결과 | 종료 전 저장 상태를 다시 조회 가능 |
| 관련 항목 | FR-LOC-004 |

**수용 기준**

1. 앱 재실행 후 기존 마커가 표시되어야 한다.
2. 활성화, 최초 진입, 방문 완료 및 마지막 알림 정보가 유지되어야 한다.
3. 손상되거나 읽을 수 없는 데이터가 있어도 앱 전체가 비정상 종료되지 않아야 한다.

#### FR-DAT-003 스키마 버전 관리

| 항목 | 내용 |
|---|---|
| 설명 | 로컬 저장 데이터에는 스키마 버전을 부여하고 앱 업데이트 시 마이그레이션할 수 있어야 한다. |
| 처리 | 앱 시작 시 저장 버전 확인 및 필요한 순차 마이그레이션 수행 |
| 결과 | 데이터 구조 변경 이후에도 기존 사용자 데이터를 가능한 범위에서 유지 |
| 관련 항목 | FR-DAT-001, FR-DAT-002 |

**수용 기준**

1. 로컬 저장소에서 현재 데이터 스키마 버전을 확인할 수 있어야 한다.
2. 이전 버전 데이터는 정의된 마이그레이션을 통해 현재 버전으로 변환되어야 한다.
3. 마이그레이션 실패가 발생하면 원인을 확인할 수 있어야 한다.

### 8.2 백그라운드 동작 품질

1. 앱은 백그라운드에서 GPS를 무제한으로 지속 실행하는 것을 기본 방식으로 사용하지 않는다.
2. 운영체제가 전달한 진입 이벤트를 수신하면 최소한의 작업으로 상태를 저장하고 알림을 처리한다.
3. 위치 감지의 즉시성은 보장하지 않으며 실제 기기 시험을 통해 허용 가능한 동작 범위를 확인한다.
4. 앱 강제 종료, 기기 재부팅 및 절전 상태에서의 동작 범위는 기술 검증 후 확정한다.

### 8.3 데이터 및 개인정보

1. 초기 버전은 마커 위치를 서버로 전송하지 않는다.
2. 앱 삭제 또는 기기 교체 시 로컬 데이터가 유실될 수 있음을 제품 정책에 반영한다.
3. 사용자가 마커를 삭제하면 앱이 관리하는 해당 마커 데이터를 제거한다.
4. 백업 및 복원 기능은 초기 범위에서 제외한다.

## 14. 요구사항 완료 기준

요구사항은 다음 조건을 모두 충족할 때 구현 완료로 판단한다.

1. 해당 요구사항과 연관된 화면, 기능, 도메인 및 데이터 설계가 완료되어야 한다.
2. 요구사항의 모든 수용 기준을 검증하는 테스트 항목이 존재해야 한다.
3. 필수 요구사항의 테스트가 실제 iOS 기기에서 통과해야 한다.
4. 위치 및 알림 권한 허용·거부 상태가 각각 검증되어야 한다.
5. 포그라운드와 백그라운드 상태의 핵심 흐름이 검증되어야 한다.
6. 요구사항 변경 시 관련 산출물과 추적표가 함께 갱신되어야 한다.
